# RF-002 — Inicio de sesión

## Identificación

| Campo | Valor |
|---------|---------|
| ID | RF-002 |
| Nombre | Inicio de sesión |
| Módulo | Autenticación |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Febrero 2026 |

## Descripción

El sistema debe permitir que los usuarios registrados inicien sesión utilizando su correo electrónico y contraseña para acceder a las funcionalidades autorizadas de la plataforma.

## Entradas

| Campo | Tipo | Obligatorio | Validaciones |
|---------|---------|---------|---------|
| email | Texto (email) | Sí | Formato válido |
| password | Texto | Sí | No vacío |

## Proceso

1. El usuario accede al formulario de inicio de sesión.
2. Ingresa correo electrónico y contraseña.
3. El frontend valida los campos obligatorios.
4. La solicitud es enviada al backend.
5. El sistema verifica la existencia del usuario.
6. Se valida que la cuenta se encuentre activa.
7. Se compara la contraseña utilizando bcrypt.
8. Se genera un token de autenticación.
9. Se registra la sesión iniciada.
10. Se retorna la información del usuario autenticado.

## Salidas

| Escenario | Código HTTP | Respuesta |
|------------|------------|------------|
| Inicio exitoso | 200 | Usuario autenticado |
| Credenciales inválidas | 401 | Error de autenticación |
| Cuenta bloqueada | 403 | Acceso denegado |
| Datos inválidos | 422 | Error de validación |

## Endpoints asociados

| Método | Ruta | Auth requerida | Descripción |
|----------|----------|----------|----------|
| POST | /api/v1/auth/login | No | Iniciar sesión |
| POST | /api/v1/auth/refresh | Sí | Renovar sesión |

## Reglas de negocio

- RN-001: Solo usuarios registrados pueden autenticarse.
- RN-002: Las credenciales deben validarse mediante hash seguro.
- RN-003: Las cuentas bloqueadas no pueden iniciar sesión.
- RN-004: Cada sesión debe generar un token único.
