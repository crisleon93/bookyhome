## Descripción

El sistema debe permitir que un usuario nuevo cree una cuenta proporcionando sus datos básicos de registro, incluyendo nombre completo, correo electrónico y contraseña. Una vez completado el registro, el sistema enviará un correo de verificación para validar la dirección electrónica antes de habilitar el acceso a la plataforma. :contentReference[oaicite:0]{index=0}

---

## Entradas

| Campo | Tipo | Obligatorio | Validaciones |
|---------|---------|---------|---------|
| full_name | Texto | Sí | Mínimo 2 caracteres, máximo 255 |
| email | Texto (email) | Sí | Formato válido, máximo 255 caracteres, único |
| password | Texto | Sí | Mínimo 8 caracteres, una mayúscula, una minúscula y un número |

---

## Proceso

1. El usuario accede al formulario de registro.
2. Ingresa nombre completo, correo electrónico y contraseña.
3. El frontend valida los campos obligatorios.
4. La información es enviada al backend.
5. El backend valida formatos, longitud y reglas de seguridad.
6. El sistema verifica que el correo electrónico no exista previamente.
7. La contraseña es cifrada utilizando bcrypt antes de almacenarse.
8. Se crea el registro del usuario en la base de datos con estado activo.
9. El sistema genera un token único de verificación de correo.
10. El token se almacena con fecha de expiración.
11. Se envía un correo electrónico con el enlace de verificación.
12. El usuario accede al enlace recibido.
13. El backend valida el token de verificación.
14. El sistema marca la cuenta como verificada.
15. El usuario queda habilitado para iniciar sesión.

---

## Salidas

| Escenario | Código HTTP | Respuesta |
|------------|------------|------------|
| Registro exitoso | 201 | Datos básicos del usuario registrado |
| Correo ya registrado | 400 | "El correo electrónico ya existe" |
| Datos inválidos | 422 | Errores de validación |
| Token inválido | 400 | Error de verificación |
| Verificación exitosa | 200 | Cuenta activada correctamente |

## Reglas de negocio

- RN-001: El correo electrónico debe ser único dentro del sistema.
- RN-002: Ninguna contraseña puede almacenarse en texto plano.
- RN-003: Todas las contraseñas deben almacenarse utilizando hashing seguro.
- RN-004: La cuenta debe crearse inicialmente con estado de correo no verificado.
- RN-005: El usuario no podrá acceder a funcionalidades protegidas hasta completar la verificación del correo.
- RN-006: El token de verificación tendrá una vigencia máxima de 24 horas.
- RN-007: Cada token de verificación podrá utilizarse una única vez.
- RN-008: El sistema deberá registrar la fecha de creación de la cuenta.
- RN-009: El sistema deberá registrar la fecha de verificación del correo electrónico.
