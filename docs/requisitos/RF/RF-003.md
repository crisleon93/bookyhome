# RF-003 — Recuperación de contraseña

## Identificación

| Campo | Valor |
|---------|---------|
| ID | RF-003 |
| Nombre | Recuperación de contraseña |
| Módulo | Autenticación |
| Prioridad | Alta |
| Estado | Implementado |
| Fecha | Febrero 2026 |

## Descripción

El usuario podrá recuperar su contraseña mediante correo de verificación.

## Entradas

| Campo | Tipo | Obligatorio | Validaciones |
|---------|---------|---------|---------|
| email | Texto (email) | Sí | Debe existir |
| token | UUID | Sí | Token válido |
| new_password | Texto | Sí | Mínimo 8 caracteres |

## Proceso

1. El usuario solicita recuperar contraseña.
2. Ingresa correo electrónico.
3. El sistema valida la existencia de la cuenta.
4. Se genera un token de recuperación.
5. Se envía un correo electrónico.
6. El usuario accede al enlace recibido.
7. Ingresa la nueva contraseña.
8. El backend valida el token.
9. La contraseña es cifrada.
10. El sistema actualiza la información.

## Salidas

| Escenario | Código HTTP | Respuesta |
|------------|------------|------------|
| Solicitud exitosa | 200 | Correo enviado |
| Usuario inexistente | 404 | Usuario no encontrado |
| Token inválido | 400 | Token inválido |
| Actualización exitosa | 200 | Contraseña actualizada |

## Endpoints asociados

| Método | Ruta | Auth requerida | Descripción |
|----------|----------|----------|----------|
| POST | /api/v1/auth/forgot-password | No | Solicitar recuperación |
| POST | /api/v1/auth/reset-password | No | Restablecer contraseña |

## Reglas de negocio

- RN-001: El token expira en 24 horas.
- RN-002: El token solo puede utilizarse una vez.
- RN-003: La contraseña debe cumplir los requisitos de seguridad.
